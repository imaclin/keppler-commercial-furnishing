# HW (Heirloom Woodwork): Platform Design Spec

**Date:** 2026-06-16
**Project:** hw
**Status:** Approved direction (homepage, category, product, admin, and customer mockups signed off). Ready for implementation planning.
**Mockups:** `docs/mockups/` (hw_home, hw_plp, hw_pdp, hw_admin, hw_customer)

---

## Goal

A premium online catalog and e-commerce platform for HW, a company selling handcrafted American (Amish-built) solid-wood furniture. It looks and functions like Arhaus: a beautiful storefront, an admin dashboard to run the catalog and orders, and a customer portal to follow quotes and orders. It operates as an e-commerce site that can transact money later; v1 is catalog plus quoting, with checkout architecture built but dormant.

## Context and positioning

- The client is established, with a builder network and existing demand. This is their flagship online presence, not a scrappy MVP. Quality of feel matters.
- **v1 scope is intentionally narrow: tables and chairs only.** Other categories (lighting, decor, outdoor, etc.) are added later on the same foundation.
- Built on the proven **artshop** foundation (catalog, image handling, admin dashboard, custom session auth, Stripe-ready), reskinned to an ultra-premium furniture brand and extended with furniture-specific features.
- Brand mark in mockups is **HW / "Heirloom Woodwork"** as a working name; final name and tagline are a fill-in.

## Tech stack and architecture

| Layer | Choice |
|---|---|
| Web | Next.js 16 (App Router) + TypeScript. Note: middleware is `proxy.ts` in Next 16. |
| UI | Custom design system (tokens below) built on Tailwind + shadcn/ui primitives |
| Backend / DB | Supabase (Postgres + RLS, Auth, Storage for furniture imagery) |
| Payments (deferred) | Stripe, architecture wired in v1, checkout disabled until activated |
| Email | Resend (quote ready, order updates, sample shipped, consultation confirmations) |
| Hosting | Vercel |

**Infra note:** production uses a dedicated, client-owned Supabase project (provisioned in Phase 0). The MIND free Supabase org is at its active-project cap, so HW gets its own project / billing. A local Postgres fallback is available for early dev if needed.

**Roles:** open customer registration (this is e-commerce, not invite-only). Two role tiers: `customer` and `staff` (admin/moderator). Storefront browse is public; favorites, quotes, orders, and the portal require a customer account; the admin dashboard requires staff.

## Design system (from the approved mockups)

- **Type:** Cormorant Garamond (display serif) + Inter (UI/body). Small all-caps labels with wide tracking for nav and eyebrows. Generous line-height.
- **Color:** warm near-monochrome. Backgrounds bone/cream (`#f7f4ef`, `#faf8f5`, paper `#fffdfa`); text espresso (`#2b2622`) / ink (`#3a322b`); single walnut accent (`#6b4f3a`); stone secondary (`#8c8175`); hairline `#e6ded2`. Color comes from the furniture, not the chrome.
- **Status tints (admin/portal):** muted ok/green, amber (in production), gray (quote), blue (shipping) on soft tinted pills.
- **Layout:** wide margins, calm grids, large editorial imagery, lots of whitespace.
- **Imagery:** warm natural light, lifestyle plus on-white product plus macro craft/joinery detail. One consistent treatment.
- **Components:** understated thin-outline and quiet-solid buttons, hairline dividers, round wood-tone swatch chips, accordions for detail, sticky add-to-cart/quote on PDP, favorite hearts, status pills, production-step tracker.
- **Motion:** slow, eased, restrained. Gentle crossfades, fade-up on scroll, soft hover zoom. Nothing fast or bouncy.

## Key page behaviors

**PDP configurator (the signature feature):** a product exposes a set of available wood species, finishes, and sizes, each optionally adjusting price. Selecting them recomputes the displayed price live. "Order a wood & finish sample" (small fee, credited to order). Primary CTA is **Request a Quote** in v1 (Add to Cart routes to the quote flow); the same button becomes Add to Cart / Checkout when payments activate.

**Quote and order flow:** customer requests a quote (cart contents or a single configured piece) → admin reviews and sends a priced quote with an expiry → customer reviews and accepts → becomes an order → moves through statuses (`quote → confirmed → in_production → shipping → delivered`), each update visible on the customer's production tracker and emailed.

## Data model (core)

```
profiles        id, email, role (customer|staff|admin), name, created_at   (+ custom session auth: users, sessions)
collections     id, slug, name, description, hero_image_url, sort_order
products        id, slug, name, category (table|chair), collection_id, short_description,
                story, base_price_cents, lead_time_weeks, region, status (draft|published),
                featured, created_at
product_images  id, product_id, url, type (on_white|lifestyle|detail), sort_order
wood_species    id, name, swatch_color, swatch_image_url, sort_order
finishes        id, name, swatch_color, sort_order
product_woods   product_id, wood_id, price_delta_cents            (which woods a product offers)
product_finishes product_id, finish_id, price_delta_cents
product_sizes   id, product_id, label, seats, price_delta_cents, sort_order
favorites       user_id, product_id, created_at
sample_requests id, user_id, wood_id, finish_id, shipping_address_json, status, created_at
quotes          id, customer_id, status (requested|sent|accepted|declined|expired),
                subtotal_cents, total_cents, valid_until, notes, created_at
quote_items     id, quote_id, product_id, wood_id, finish_id, size_id, quantity,
                unit_price_cents, configuration_json
orders          id, customer_id, quote_id, status (quote|confirmed|in_production|shipping|delivered|cancelled),
                payment_status, subtotal_cents, total_cents, shipping_address_json,
                created_at, est_delivery_date
order_items     id, order_id, product_id, wood_id, finish_id, size_id, quantity,
                unit_price_cents, configuration_json, title_snapshot, image_snapshot
order_status_history id, order_id, status, note, created_at
messages        id, customer_id, sender (customer|staff), body, read_at, created_at
appointments    id, customer_id, type (virtual|in_person), starts_at, status, notes, created_at
content_blocks  id, key, payload_json        (homepage and editorial content, CMS-lite)
```

Quote and order items snapshot the configured selection (wood, finish, size, computed unit price) so historical records never drift when catalog pricing changes (the artshop snapshot pattern).

## User flows

1. **Browse → configure → request quote → review → accept → track** (primary)
2. **Order a wood/finish sample** → mailed → return to buy
3. **Save favorites** → revisit in portal
4. **Book a design consultation** → confirmation → appears in portal and admin
5. **Admin:** create product with images, woods, finishes, sizes → publish → receive quote request → price and send → manage order through statuses → message customer
6. **Trade/business inquiry** (lightweight form in v1; full trade pricing later)

## Build phases

- **Phase 0 — Foundation:** repo, Next 16 + Supabase + Tailwind/shadcn, design tokens and fonts, base layout (header, nav, footer), custom session auth with customer/staff roles, schema migration baseline. *Outcome: themed shell you can log into as customer or staff.*
- **Phase 1 — Catalog + Admin catalog management:** products/collections/woods/finishes/sizes data + admin CRUD with image upload. *Outcome: staff can build the catalog.*
- **Phase 2 — Storefront:** home, PLP (tables/chairs) with filters/sort, PDP with the live configurator, collections, search, cart-to-quote. *Outcome: the public premium site.*
- **Phase 3 — Accounts + portal:** customer registration/login, favorites, sample requests, portal dashboard. *Outcome: customers have a home.*
- **Phase 4 — Quotes + orders + messaging:** quote request/send/accept, order creation, status flow + production tracker, customer-admin messaging, email notifications. *Outcome: the full sales loop.*
- **Phase 5 — Consultations + content + polish:** appointment booking, editorial/static pages, trade inquiry, motion polish.
- **Phase 6 — Payments (deferred):** Stripe checkout, deposits, order payment status.

Phases 0 to 4 are the real v1 deliverable. Each phase gets its own implementation plan; this spec is the shared reference.

## Out of scope for v1

Live payments/checkout (Phase 6), categories beyond tables and chairs, room planner, full trade pricing tiers, financing/credit, multi-currency, reviews. All anticipated by the architecture, none built in v1.
